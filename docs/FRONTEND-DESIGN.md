# KokuuSkin 整站前端设计规范

> 版本 1.0 · 2026-11-03  
> 状态：设计基线，供首页改版及后续全站页面统一使用  
> 当前实现：BlessingSkin 6 / Laravel + 插件视图（Twig、Blade）+ React 前端页面；首页由 `kokuu-appearance` 客户端渲染。

## 1. 产品与设计目标

KokuuSkin 是 Minecraft 皮肤、角色外观与 Yggdrasil 账号验证服务。前端首先应让用户完成任务：找皮肤、预览、上传、保存到衣柜、配置启动器。Minecraft 是内容与图像来源，界面不应模拟复古方块 HUD；整体采用 KokuuSkin 现有品牌与原神式精致视觉：真实世界场景、角色展示、克制的光效和清楚的操作层级。

### 设计原则

1. **内容先于装饰**：首屏立即说明这是 Minecraft 皮肤站，并突出浏览皮肤库。
2. **真实图片承担视觉**：用 MC 场景和实际皮肤预览；禁止把纯 CSS 图形、像素网格或小图标当成主视觉。
3. **品牌一致**：暖纸白底、深紫文字、青色行动色、淡紫辅助色；避免整页深黑、紫色渐变泛滥与中秋/星月主题误用。
4. **实际任务可达**：重要入口使用有清晰标签的链接/按钮，避免只显示装饰图标。
5. **渐进增强**：主题、轮播和滚动动效失败时，页面内容与导航仍可用。
6. **状态清楚**：加载、空结果、错误、禁用、成功均应有真实反馈，不以动画代替状态文案。

## 2. 信息架构

### 公共页面

- 首页 `/`：品牌介绍、皮肤库主入口、精选皮肤、使用流程、Yggdrasil 说明。
- 皮肤库 `/skinlib`：搜索、皮肤/披风筛选、排序、预览、收藏、详情。
- 皮肤详情 `/skinlib/show/{id}`：大预览、作者/模型类型、收藏与使用操作。
- 上传 `/skinlib/upload`：文件选择、预览、名称/模型信息、上传状态与错误恢复。
- 登录/注册 `/auth/*`：保留内核表单行为，统一外观但不重写认证流程。

### 登录后

- 用户中心 `/user`：余额、签到、最近活动与常用动作。
- 衣柜 `/user/closet`：当前角色、已保存皮肤、切换/上传入口。
- 积分 `/plugin/kokuu-credit/*`：余额、流水、签到状态。
- 抽卡 `/plugin/kokuu-lottery`：金粒、钻石、绿宝石，单抽/十连、保底与结果。

### 管理员

- 管理后台保持 AdminLTE 信息架构，使用统一 tokens、表单、表格、状态色；不把用户端营销视觉搬入后台。
- 页面容器、导航、表单、列表不改业务 DOM 语义，只按 UI Kit 类名和范围样式增强。

## 3. 首页版式规范

### 桌面首屏

1. **玻璃顶栏**：KokuuSkin 品牌、皮肤库、登录/注册或用户中心/衣柜、主题切换。导航高度 60–68px，滚动时可固定。
2. **大幅 Hero**：使用用户提供的三张高光影 MC 奇幻宣传图：暮光村庄、雪山清晨、丛林神庙。图中已有完整角色，因此不再叠加低分辨率皮肤预览。文字位置按图分别为左侧、左上、右上，避免遮脸；用局部渐变保证对比。图片不烧录标题、Logo、按钮。
3. **主行动**：主按钮“探索皮肤库”；次按钮按认证状态显示“创建账户”或“我的衣柜”。首屏只保留 1 个主 CTA。
4. **角色精选**：从皮肤库预览 API 展示真实条目；名称、Steve/Alex 模型与详情链接必须同步变化。图片不可加载时显示可读占位与继续浏览链接。
5. **使用流程**：挑选皮肤 → 保存到衣柜 → 配置启动器登录。用简洁步骤条，不用抽象品牌宣言填充空间。
6. **能力入口**：皮肤库、上传、Yggdrasil 登录验证等实际功能，每项说明可做什么并提供链接。
7. **页脚**：皮肤库、上传、登录、联系邮箱及版权信息。

### 响应式

- ≥1100px：Hero 双层构图，文案列与角色/场景视觉区域比例约 4:6；完整导航。
- 641–1099px：文字和视觉纵向排列，Hero 图片不裁掉角色；服务卡 2 列。
- ≤640px：导航收敛为可访问菜单/简洁链接；Hero 主视觉优先，标题、按钮不覆盖角色脸部；服务卡单列；CTA 可满宽。
- 所有图片容器定义稳定 `aspect-ratio`/最小高度，避免加载后跳动；最窄宽度 320px 不出现横向滚动。

令牌唯一来源为 `kokuu-appearance/assets/tokens.css`。禁止各业务页重复定义另一套全局色板。业务插件独立可用，变量需保留 fallback。

| `--k-surface`       | 主表面     | `#FFFFFF`                       |

| `--k-text`          | 主文本     | `#241A45`                       |
| `--k-text-2`        | 次文本     | `#6B6483`                       |

| `--k-brand-ink`     | 品牌深紫   | `#2B1F52`                       |
| `--k-brand-rain`    | 主强调青   | `#0FA3A3`                       |

## 5. 排版与布局

- 字体：`--k-font-sans`；数值/技术标识可使用 `--k-font-mono`。
- 标题不使用多重硬描边/负字距；中文字距保持自然（`letter-spacing: 0`，必要时按字重做微调）。
- Hero 标题按容器设定明确 `clamp()` 上下限，不依赖 viewport 单独缩放导致极端尺寸。
- 内容最大宽度使用 `--k-max-w`；标准间距使用 `--k-s-1...--k-s-9`，4px 倍数。
- 正文行高 1.55–1.8；单行文本不拉长，长说明限制在舒适阅读宽度。
- 重复卡片统一对齐标题、描述和操作；卡片圆角不大于令牌 `--k-r-xl`，避免嵌套卡片。

## 6. 组件规范

使用 `UI-KIT.md` 中的 `k-*` 语义组件：`.k-container`、`.k-card`、`.k-btn`、`.k-badge`、`.k-field`、`.k-table`、`.k-stat`、`.k-alert`、`.k-grid`。首页可有 `kokuu-*` 专属布局类，但业务组件仍采用同一按钮、焦点、圆角和色彩令牌。

- 主按钮：一个页面一个主行动；次按钮用 outline/ghost，避免两个同权重的彩色渐变 CTA。
- 卡片：可点击则整卡为链接且焦点可见；纯展示卡片不伪装成按钮。
- 图片：alt 描述场景或皮肤；装饰图使用空 alt 和 `aria-hidden`。
- 轮播：提供可聚焦场景按钮、`aria-pressed`、可暂停或减少动态行为；轮播期间确保当前角色名/链接同步。
- 表单：保留内核验证与提交；标签、帮助文案、错误状态对应真实输入控件。

## 7. 动效与状态

- 页面内容默认可见；滚动揭示仅为渐进增强，JS/IntersectionObserver 失败不得隐藏内容。
- 轮播只在页面可见且用户未启用 `prefers-reduced-motion: reduce` 时自动播放；减少动态时停用自动轮播和缓慢缩放。
- 常规交互 150–250ms；图片切换淡入约 500–1000ms；避免持续粒子、大面积位移或闪烁。
- 按钮 hover/focus/active/disabled 状态必须可区分；键盘焦点至少 2px 清晰外框。
- 网络错误、皮肤预览不可用、未登录均有静态退化状态与可执行链接。

## 8. 真实皮肤展示契约

首页精选皮肤必须来自皮肤库公开条目或后台可配置数据；禁止静态复制用户皮肤到主题仓库。

- 预览图 URL 使用站内 `/preview/{id}?height={n}&png` 端点，保持同源缓存与权限规则。
- `id`、名称、模型类型、详情 URL 作为一个数据对象同步切换。
- 用户皮肤名/昵称写入 HTML 前转义；图片失败时显示默认场景/占位且不阻塞 CTA。
- 当前首页原型取公开皮肤库条目 13/12/11/9 做本地视觉验证；上线前确认这些样本可长期公开或改由后台精选配置。
- Hero 图片由后台 `hero_background`、`hero_background_2`、`hero_background_3` 覆盖；`hero_image` 保留为旧版单张配置。真实皮肤卡在 Hero 下方独立展示，不与宣传图里的角色重复叠加。

## 9. 主题与路由契约

- 保留 `window.KOKUU_CONFIG` 字段：`hero_title`、`tagline`、`intro`、`hero_image`、`footer_note`、`contact_email`。
- 保留 `kokuu_theme` localStorage key 和 paper/void 两态。
- 保留 `window.blessing.base_url` 做全部同源路由与图片 URL，禁止硬编码生产域名。
- 保留登录态 `/user` 检测，访客显示登录/注册，已登录显示用户中心/衣柜。
- 首页继续由 appearance 插件接管，仅 `/` 页面；不得改变内核模板、认证表单、Skin Library 或管理后台业务逻辑。

### 皮肤卡组件

- 预览图固定比例，底部名称最多两行，Steve/Alex/披风采用文字徽章。
- 作者与收藏数使用真实数据；不以随机数字填充视觉。
- 收藏按钮独立于详情链接，禁止嵌套 `<a>`；触摸目标至少 44×44px。
- 预览图片失败保留卡片标题与详情入口，提供“预览暂不可用”状态。

### 祈愿动画规格

- 明确阶段：请求中 → 星空/世界转场 → 按最高品质蓝/紫/金出现流光 → 奖品卡揭晓 → 结果总览。
- 动画不决定中奖；所有结果来自后端，金额和品质不能由浏览器随机。
- 跳过只跳过表现，仍显示完整已入账结果；用户确认关闭结果，不自动闪退。
- 十连逐张揭晓后保留 10 张总览；键盘 Esc、关闭按钮、焦点恢复都可用。
- 减少动态时直接展示结果卡；不白等动画时长。
- 金粒/钻石/绿宝石估值与兑换必须以后端规则为准；本设计文档不改变经济参数。

## 12. 图片与美术交付规范

- 三张当前图由用户提供，源文件保留；推荐输出 WebP/AVIF，横图约 1920–2560px，目标单张 250–500KB。
- 图 1：暖色暮光村庄，角色在右；图 2：雪山清晨，角色偏左；图 3：丛林神庙，角色中左。
- 风格统一为高质量 MC 游戏宣传渲染，允许二次元角色服饰与奇幻气氛；禁止再次换成程序绘制的低分辨率像素简画。
- 桌面文案按构图设安全区；手机独立设置 `object-position`，不能将所有图片一律居中裁切。
- 图片需要替换时使用后台字段；不改核心模板，不要求重新编译 React。

## 13. 实施顺序与交付边界

1. **本轮：首页**：三张宣传图、独立文案锚点、轮播暂停/手动选择、主题切换、真实皮肤预览、功能入口、三步使用流程。
2. **第二阶段：公共皮肤流程**：皮肤库、详情、上传、认证页；先验证原业务交互，再统一外观。
3. **第三阶段：用户中心**：角色、衣柜、金粒、签到；统一余额称呼与来源提示。
4. **第四阶段：祈愿**：大图场景、完整抽卡动画与稳定结果总览。经济系统/保底需独立事务与幂等验证，不与纯视觉改版一起扩大变更。
5. **第五阶段：管理员界面**：筛选、表格、配置、反馈；官方插件代码保持原样，通过外观适配统一。

发布门槛：真实浏览器桌面/手机检查、API 契约验证、资源版本生效、关键交互回归。HTTP 200、颜色数量统计、grep 命中都不能代替视觉与行为验收。
